# Architecture Decision Records

Architecture Decision Records, or ADRs, document important technical decisions that should remain understandable over time.

Use an ADR when a decision:

- affects architecture or long-term maintainability;
- establishes a project-wide convention;
- chooses between meaningful alternatives;
- changes how future work should be designed;
- needs context beyond a changelog entry.

Each ADR should normally include:

- context;
- decision;
- consequences;
- alternatives considered;
- status.

ADR files should use a numbered name such as:

```text
ADR-001-example-decision.md
```

No ADRs have been created yet. Existing historical decisions remain in `CODEX/BITACORA.md` until they are promoted into formal ADRs.
